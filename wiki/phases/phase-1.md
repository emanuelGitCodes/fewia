## Verification

Run on 2026-08-31 with Docker Desktop 29.6.1 and an empty volume:

- `docker compose up -d --build` started both services; `postgres`
  reached healthy.
- `curl localhost:8000/healthz` returned HTTP 200 and `{"status":"ok"}`.
- `uv run alembic upgrade head` exited 0 on the clean database. `psql
  \dt` then listed all six tables plus `alembic_version`. The agent also
  proved a `downgrade base` and a second `upgrade head`.
- `psql \d` on all six tables matched §4: column names, SQL types,
  nullability, primary keys, foreign keys, `now()` defaults, and the
  `steps >= 0` check.
- `uv run ruff check app tests`, `uv run ruff format --check app tests`,
  `uv run mypy --strict app`, and `uv run pytest` all passed. 9 tests
  pass.
- GitHub Actions did not run. Nothing was pushed, so CI stays unproven.

## Decisions inside the phase

- The identity columns use `GENERATED BY DEFAULT AS IDENTITY`, not
  `BIGSERIAL`. Both give a bigint auto-increment column.
- The `steps` check carries the name `ck_daily_health_steps`. Alembic
  needs a name to drop a constraint.
- `alembic/env.py` reads the URL from `app.config.settings`.
  `alembic.ini` holds no URL, so no credential sits in source.
- The Postgres password `fewia` is a local development value in
  `compose.yaml` and in CI. AWS MUST read `DATABASE_URL` from Secrets
  Manager instead.
